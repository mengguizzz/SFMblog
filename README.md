# 🌌 Single-File-MD-Blog (极简单文件 Markdown 博客)

## 写在最前

最初的想法来自 [Docsify](https://docsify.js.org/#/)，第一版由 Gemini 生成。
现在这一版是在保留「零数据库 / 单文件 Markdown」这个核心思路的前提下，
重做了视觉设计与交互，并修掉了一批会真正踩到的问题。

我的博客：[梦归の小站](https://ztyou.cn)

一个写给折腾家和极客的极轻量级、**零数据库**个人博客系统。
抛弃了臃肿的 MySQL 和繁杂的框架，回归纯文本的本质 —— 所有文章都存在一个 `.md` 文件里。

## ✨ 核心特性

- **📄 零数据库**：`blogs/default.md` 就是数据库，用 `---POST---` 分隔文章，备份博客只需复制一个文件夹。
- **💻 极客控制台**：沉浸式深色双栏 Markdown 编辑器，实时预览、代码高亮、快捷键、字数统计、草稿自动保存。
- **🖼️ 原生剪贴板图床**：编辑器里 `Ctrl+V` 粘贴截图，自动上传并转成 Markdown 图片语法，**服务端会校验真实图片类型**。
- **🔒 服务器端鉴权**：没有公开的登录入口，点击页脚头像进入隐藏的 `login.html`。
  密码用 **bcrypt** 存储、只在登录那一次请求里发送，服务器换回一个随机会话 id；
  浏览器里存的是会话 id 而不是明文密码，退出登录即刻失效，连续失败会被锁定。
- **🧩 服务端渲染**：文章列表 / 正文由 `api.php` 按需返回，
  **`blogs/default.md` 不允许被直接下载**，所以回收站里的文章、草稿不会外泄。
- **🎨 液态玻璃 UI**：动态极光背景 + 高斯模糊玻璃卡片，☀️ 白天 / 🌙 黑夜模式丝滑切换，且跟随系统主题。
- **📖 阅读体验**：文章页带阅读进度条、右侧目录（滚动高亮）、代码块复制、上下篇导航、标题锚点。
- **📈 访问统计**：基于 `blogs/counter.txt` 的极简全站访问计数。

## 🛠️ 技术栈

- **前端**：HTML5、CSS3（原生自定义属性 / Grid / backdrop-filter）、Vanilla JS、Marked.js、Highlight.js
- **后端**：PHP 8.x
- **环境**：任何支持 PHP 的 Web 服务器（Nginx + PHP-FPM / OpenResty，1Panel 等面板环境均可）
- **无构建步骤**：改完文件直接上传即可

## 🔌 接口一览

| 接口 | 是否需要登录 | 说明 |
| --- | --- | --- |
| `GET api.php?action=list` | 否 | 文章列表：id / 标题 / 日期 / 标签 / 摘要 / 阅读时长。**不含正文，不含已删除文章** |
| `GET api.php?action=post&id=N` | 否 | 单篇文章（含正文）。已删除的返回 404 + `deleted:true` |
| `GET api.php?action=counter` / `peek` | 否 | 访问量 +1 / 只读取 |
| `POST action=login` | – | 用密码换 `sid`（失败会累计，超过 8 次锁 15 分钟） |
| `POST action=logout` | 是 | 注销当前会话 |
| `POST action=all` | 是 | 控制台用：全部文章（含回收站）和正文 |
| `POST action=add / edit / delete / restore` | 是 | 增 / 改 / 软删除 / 恢复 |
| `POST action=trash / trash-purge` | 是 | 列出回收站 / 彻底删除 |
| `POST action=upload` | 是 | 图床上传（校验真实图片类型，上限 10MB） |

所有需要登录的接口校验的是 `sid`，**不再接受"把密码当 token 发"**。

## 🚀 部署指南

### 1. 生成密码哈希

```bash
echo -n 'YourPasswordHere' | sha256sum
```

> ⚠️ `-n` 不能省，否则会把换行符也算进去，导致永远登录不上。

### 2. 配置密钥

先生成一个 bcrypt 哈希（**不要再用裸 sha256**，它快到可以暴力破解）：

```bash
php tools/make-password.php '你的新密码'
```

把输出复制成 **`config.php`**：

```php
<?php
$EXPECTED_HASH = '$2y$12$...';   // tools/make-password.php 的输出
```

`config.php` 已在 `.gitignore` 里，不会被提交到仓库。
**没有配置它的话，登录页会明确提示「服务端还没配置密钥指纹」，不会静默放行。**

> 兼容旧配置：如果 `$EXPECTED_HASH` 还是 64 位十六进制，程序仍然接受（按 sha256 比对），
> 但登录时会返回 `legacy: true` 提醒你尽快换掉。

### 3. 上传并授权

把整个目录上传到 PHP 站点根目录，然后确保 `blogs/` 和 `src/images/` 可写：

```bash
chown -R www-data:www-data blogs src/images
# 或者
chmod -R 755 blogs src/images
```

### 4. Nginx 参考配置

```nginx
server {
    listen 80;
    server_name your.domain.com;

    root /var/www/sfmblog;
    index index.html;
    charset utf-8;
    client_max_body_size 12m;          # 图床上传上限

    location = /config.php { deny all; }   # 密钥文件永远不对外
    location ~ /\.          { deny all; }

    location / {
        try_files $uri $uri/ =404;
    }

    location ~ \.php$ {
        include snippets/fastcgi-php.conf;
        fastcgi_pass unix:/run/php/php8.5-fpm.sock;   # 按实际版本改
        fastcgi_read_timeout 120s;
    }

    location ~* \.(jpg|jpeg|png|gif|webp|svg|css|js|ico|woff2?)$ {
        expires 7d;
        add_header Cache-Control "public";
    }
}
```

改完执行 `nginx -t && systemctl reload nginx`。

> **缓存策略**：`html` / `js` / `css` 都是 `no-cache`（每次回源校验，ETag 命中就是 304），
> 图片长缓存。页面里的 `style.css?v=...` / `blog.js?v=...` 是版本号，
> 用来踢掉历史缓存 —— 注意**别把 `expires 7d` 加回 js/css**：
> 之前这么干过一次，改完 `blog.js` 后老访客浏览器里还是旧代码，页面直接白掉。

## 🎮 使用方法

1. 访问首页 `index.html`。
2. 点击页面右下角页脚的**头像**，进入隐藏登录页。
3. 输入密码，校验通过后进入控制台。
4. 顶部工具栏可以插入标题 / 加粗 / 列表 / 代码块 / 表格等；`Ctrl+V` 直接粘图上床。
5. 点「发布」写回 `default.md`；点「文章」抽屉可以载入历史文章继续编辑或删除。
6. 登录状态下，文章页会出现「✏️ 编辑此文」按钮。

常用快捷键：`Ctrl+B` 加粗、`Ctrl+I` 斜体、`Ctrl+K` 链接、`Ctrl+S` 保存发布。

## 🧾 文章格式

每篇文章就是这个样子，`---POST---` 之间即为一篇：

```markdown
# 文章标题
<!-- DATE: 2025-08-13 | TAG: Linux, 教程 -->

正文内容……

---POST---

# 第二篇
<!-- DATE: 2025-08-01 | TAG: 折腾 -->

……
```

- `TAG` 支持用逗号分隔多个标签；
- 空块不计入编号，所以手动多敲几个换行不会让文章的 `id` 错位；
- 首页摘要会自动剥掉代码块、图片、标题和链接，只保留正文第一段。

### 删除 = 打标记，不是删掉

删除一篇文章时，PHP **不会**把它从 `default.md` 里移除，只是在 `DATE` 注释下面插一行：

```markdown
# 某篇文章
<!-- DATE: 2025-08-13 | TAG: Linux -->
<!-- DELETED: 2026-10-10 10:14:35 -->

正文还完整地留在这里……
```

前台渲染时会跳过带这个标记的块，所以在控制台的「回收站」里点恢复，只要把那一行删掉即可。

这么做有两个好处：

1. **原文永远还在**。就算哪天 PHP 挂了、程序写错了，正文仍然明明白白躺在 `default.md` 里，
   用记事本就能救回来。
2. **链接不会失效**。文章 `id` 是它在文件里的**原始块下标**，删除不会让块移动，
   所以删掉第 3 篇不会导致第 4 篇之后的 `post.html?id=N` 集体改号。

控制台回收站里的「彻底删除」才会真正把块从文件中移除 ——
这一步会让后面的文章下标前移，界面上会专门提醒。

## ✨ 视觉效果一览

全站的基调是「极客终端 + 液态玻璃」，所以下面这些不是随手加的装饰，
都在同一个母题上：

| 效果 | 说明 |
| --- | --- |
| **终端雨** | 代码字形（`01 <> {} $ #` + 半角片假名）从页面上方落下，玻璃卡片会把它们折射掉。**默认关闭** —— 见下方"性能"，在页面上敲 `rain` 打开。 |
| **滚动浮现** | 元素进入视口时淡入并上移，同组元素按 `--d` 依次错开 70ms。首屏、归档时间轴、关于页面板、文章卡都接了。 |
| **指针柔光** | 一个跟着鼠标走的模糊光斑，外加玻璃卡上的高光（`--mx/--my` 随指针写入）。只在真有鼠标的设备上启用。 |
| **主题扩散** | 点白天/黑夜开关时做一个圆形擦除，**圆心固定在按钮上**、半径取到离按钮最远的角。而且**两个方向不一样**：白天 → 黑夜是深色从按钮扩散铺满整屏（820ms）；黑夜 → 白天反过来了，是整页往按钮里收缩、像被吸进去（760ms）。 |
| **打字机** | 首屏那张卡片里的 `> root access granted` 会一个字一个字敲出来，末尾留一个闪烁光标。 |
| **卡片扫光** | 鼠标悬浮文章卡时，一道斜向细光扫过。 |
| **主按钮转光** | 主按钮外圈有一道缓慢旋转的高光。 |

### 透明玻璃与折射（几个必须知道的坑）

玻璃不是普通毛玻璃，而是**真折射**：JS 生成一张「透镜位移图」（边缘把采样点推到外侧），
交给 SVG 滤镜，再用 `backdrop-filter: url(#sfm-lens)` 弯折背后的画面。
中间几乎不动，边缘会把外面的画面吸进来 —— 终端雨、网格都会跟着弯。

实现上有三个坑，都踩过，写在这里免得以后改回去：

1. **`backdrop-filter` 不能声明在 `will-change` 元素的后代上。**
   `will-change` 会让元素成为 *backdrop root*，后代的 `backdrop-filter` 只能采样到
   这个元素内部的内容。所以 `[data-reveal]` 上**绝对不能有 `will-change`**
   （`.post-card` 自己就是 `[data-reveal]`，会被自己废掉）。
   实测：加上就完全没有折射（差异 0.07%），去掉是 84%。

2. **SVG 滤镜里的小单位要说清楚。**
   外层 `<svg>` 是 `width="0" height="0"` 时，滤镜区域若用百分比会被按 0×0 解析、
   直接塌成空的 —— 现象是"滤镜被静默忽略"。用 `primitiveUnits="objectBoundingBox"`
   让 `feImage` 的 `0,0,1,1` 相对元素自身，就对了。

3. **背景动得越少，玻璃越便宜。**
   只要背景每帧都在变，所有 `backdrop-filter` 都得跟着每帧重算。
   实测把极光漂移从"连续"改成"离散 steps(30)"或静止，GPU 从 41% 降到 22%；
   再配合去掉噪点层的 `mix-blend-mode`、把极光的 `blur(70px)` 换成自带柔化的径向渐变，
   整站 GPU 从 65~97% 降到约 18%。

   > 想恢复极光漂移：把 `:root` 的 `--drift-play` 改成 `running`。

### 🥚 彩蛋

在页面上（别在输入框里）连续敲 **`rain`** —— 终端雨按 `关闭 → 常规 → 加强 → 关闭` 循环。

### 关于动效的几个约定

- 所有隐藏态都挂在 `html.has-reveal` 上，而这个类由 JS 添加。
  **JS 挂了、或者被墙了，元素就是正常可见**，不会出现整页空白。
- 另有 3 秒兜底：万一观察器没触发，强制全部显示。
- 系统开了「减少动态效果」时：不渲染雨、不启动打字机，内容直接可见。
- 雨和光斑都是 `pointer-events: none`，不影响点击。
- 主题扩散依赖浏览器的 View Transitions（Chrome/Edge、Safari 18+、Firefox 139+ 都支持）；
  不支持的浏览器会平滑地直接切换，不会出错。

### 性能：为什么终端雨默认是关的

只要**背景在动，玻璃背后的画面就每帧都在变**，页面上所有 `backdrop-filter`
都得跟着重算。所以这里的取舍是"背景越安静，玻璃越便宜"。

实测（Chrome 154，本机，Windows 的 `\GPU Engine(*)\Utilization Percentage`）：

| 状态 | GPU 占用 |
| --- | --- |
| 最初：极光连续漂移 + 70px 高斯模糊 + 全屏混合模式噪点 + 终端雨 | 65 ~ 97% |
| 去掉噪点层的 `mix-blend-mode: overlay` | −17 |
| 极光的 `filter: blur(70px)` 换成自带柔化的径向渐变 | −10 |
| 极光改离散步进 `steps(30)` | 41 → 22 |
| 极光完全静止 | 17.6 |
| **终端雨默认关闭（现状）** | **≈ 6.8** |

> 有意思的是：把雨**调淡**几乎不省（13.9% → 仍 7.3 个百分点），
> 因为开销不在"看得见多少"，而在"canvas 还在重绘"。

极光想恢复漂移：把 `:root` 的 `--drift-play` 从 `paused` 改成 `running`。

### 背景纹理（五选一）

背景纹理**全部由 CSS 渐变生成，没有任何栅格图** —— 所以不存在"不同设备
分辨率/DPR 下被拉伸、裁切、模糊"的问题，体积也是 0。

改 `<html data-pattern="...">` 就能换：

| 值 | 效果 |
| --- | --- |
| `grid` | **默认**。彩色方格本：22px 小格 + 每 4 格一条略深的主线，带紫调 |
| `iso` | 等距网格，工程图纸感 |
| `dots` | 点阵，最安静，适合长时间阅读 |
| `contour` | 等高线，曲线更有设计感 |
| `none` | 不要纹理（玻璃会变成纯透明，折射失去参照物） |

纹理线用的是单独的 `--paper-line` / `--paper-line-strong`，不占用界面的 `--line`。

> 纹理不只是装饰：玻璃的折射需要**直的、有细节的东西**当参照。
> 实测把背板换成光滑渐变之后，位移几十像素也几乎看不出来。

### 关于「手机白天模式下背景发灰」

这**不是 bug**：站点默认跟随系统的深浅色偏好，手机开了深色模式就进深色主题。
手动切过一次之后就以你选的为准（存在 `localStorage.theme`）。

想让站点**不管系统设置、一律默认浅色**，把 `index.html` 等页面 `<head>` 里
这段的第一行删掉即可：

```js
t = window.matchMedia('(prefers-color-scheme: dark)').matches ? 'dark' : 'light';
// 改成
t = 'light';
```

排查这类设备相关问题时，在地址后面加 `?debug` 会弹出一个面板，
把主题、系统偏好、`color-scheme`、实际背景色、DPR、UA 都列出来 ——
模拟器复现不了的问题，只能靠真机把环境报回来。

### 默认主题按「系统时间」走

没有手动切过主题时，**按访问者的本地时间**决定：

| 时间 | 默认主题 |
| --- | --- |
| 07:00 ~ 18:59 | ☀️ 浅色 |
| 19:00 ~ 06:59 | 🌙 深色 |

手动点过开关之后就以你的选择为准（存在 `localStorage.theme`），不再随时间变。
改边界时间：六个页面 `<head>` 里的 `h >= 7 && h < 19`。

> 注意：**不要用 `prefers-color-scheme`**。之前是按系统深浅色偏好来的，
> 结果手机开着深色模式时，白天访问也是深色，很容易被误认为"背景发灰"的 bug。

### 看板娘（Live2D）

桌面端左下角会有一个 Live2D 看板娘，鼠标悬停能互动、可以拖拽，
点工具条可以看**一言** / 关于 / 收起。

显示尺寸 **250px**（库默认是 300px，在 `css/style.css` 里用 `#waifu #live2d` 压小了；
改这一个值就能整体缩放，工具条和气泡的位置也跟着调好了）。

**只在桌面端加载**：要求 `(hover: hover) and (pointer: fine)` 且视口 ≥1024px。
手机上不是"隐藏"，而是**一个字节都不下载** —— 连那几百 KB 的脚本和模型都不去取。
系统开了「减少动态效果」时同样不加载。

**收起之后会记住**，下次只留左下角一个小按钮可以召唤回来。

**默认关闭**：首次访问左下角只有一个 🐾 按钮，点它才加载（免得占地方、也免得白吃 GPU）。
点过之后会记住"已开启"，下次自动出现；再点工具条里的 ✕ 收起，就又回到关闭状态。

#### 为什么选 live2d-widgets 而不是更流行的 oh-my-live2d

实测出来的：oh-my-live2d 内部用 PixiJS，在严格 CSP 下会直接报

```
Current environment does not allow unsafe-eval,
please use @pixi/unsafe-eval module to enable support.
```

**渲染不出来**，除非把 CSP 放开 `'unsafe-eval'`。而 `live2d-widgets`（stevenjoezhang 的维护版）
用的是 Cubism 2 核心，同样条件下 **canvas 正常渲染、零 CSP 违规、零报错**。

同一份 CSP 下的对照实验：

| 方案 | canvas | 报错 |
| --- | --- | --- |
| oh-my-live2d 0.19.3 | 0 个 | 1 条 unsafe-eval |
| live2d-widgets 1.0.1 | **800×800 已渲染** | 0 条 |

看板娘的组件和模型**全部自托管**（见下面「模型来源」），所以它本身没让 CSP 多放行任何域名。
CSP 里额外放行的只有两个：

| 域名 | 用途 |
| --- | --- |
| `https://cdn.jsdelivr.net` | Markdown 渲染（marked / highlight.js） |
| `https://v1.hitokoto.cn` | 「一言」按钮（只有点了才请求，详见下面） |

而且**始终没有放开 `unsafe-eval`**。

#### ⚠️ GPU 代价：约 15 个百分点

这是加它必须知道的代价 —— Live2D 是持续 60fps 的 WebGL 渲染：

| 状态 | GPU |
| --- | --- |
| 看板娘显示中 | 20.5% |
| 看板娘收起后 | 5.8% |

好的一面是**收起它就等于关掉**（显示 `none` 后渲染就停了），而且这个选择会记住。
所以它是**默认关闭**的：不点那个 🐾 按钮，就一个像素都不渲染。

> 这两个数是用**独立 user-data-dir 启动的 Chrome**、只统计它自己的进程测出来的。
> 早先按"全部 chrome.exe"汇总的测法在你还开着浏览器时会严重失真（实测能跑到 80%+）。

#### 工具条上的「一言」

用的是组件自带的 `hitokoto` 工具，点了会拿一句 [hitokoto.cn](https://hitokoto.cn/)
的句子显示在气泡里。**这是全站唯一一个第三方请求**，只有真的点那个按钮才会发出去，
且只连 `https://v1.hitokoto.cn`（CSP 里单独放行了这一个域名）。

两个地方给它打了补丁，都在 `js/blog.js` 里：

1. **接口挂了要有兜底。** 组件内部是裸的 `fetch("https://v1.hitokoto.cn")`，
   **没有 try/catch** —— 断网或者接口抽风时是一条未捕获报错 + 气泡什么都不出，
   按钮点了像没反应。这里在 `initWidget` 之前把 `window.fetch` 包了一层：
   **只有一言这个地址**失败时才返回一句本地诗词（8 句经典诗词，出处都可靠），
   其余请求一律原样透传。
2. **点了要真的显示。** 组件用 `sessionStorage` 里的 `waifu-message-priority`
   挡消息：新消息优先级不高于当前那条就直接丢弃。刚进页面时欢迎语优先级更高，
   这时候点「一言」会**请求发了、句子拿到了、气泡里却还是欢迎语**。
   所以额外挂了一个捕获阶段的 click 监听，在组件自己的 handler 之前把那个优先级清掉 ——
   「用户主动点的一言」永远显示得出来。

验证脚本 `work/qa/verify-hitokoto.js` 两种场景都覆盖了：
正常联网（气泡换成真的句子）和把接口掐掉（气泡换成本地句子、**且不能有未捕获报错**）。

### 文章评论（自己实现的）

**只在文章页的底部**，首页 / 归档 / 关于都没有 —— 评论本来就该跟着文章走。

评论**存在本站自己的服务器上**，一篇一个文件：

```text
comments/
├── 0.json                 第 0 篇文章的评论
├── 1.json
├── .rate.json             限流记录（按 IP 哈希，10 分钟窗口）
└── .backup/               每次写入前的上一版，手滑还能捞
```

跟 `blogs/default.md` 是同一个路子：**不引数据库**，直接看、直接备份、直接拷走。
和 giscus / utterances / Disqus 那几套比，最大的好处是不用再挂一个外部依赖 ——
既不用把仓库公开、给它装 App，访客也不用注册，页面上更是一个第三方请求都没有。

#### 防滥用：三层，都不需要访客做任何事

| 层 | 做法 | 结果 |
| --- | --- | --- |
| 蜜罐 | 表单里藏一个屏幕外的输入框，真人看不见、机器人爱填 | 填了就判为 `spam` |
| 停留时间 | 提交时带上"打开页面到现在过了多久"，不足 3 秒的判为脚本 | 判为 `spam` |
| 限流 | 按 IP 哈希：**两条之间至少 20 秒，10 分钟内最多 8 条** | 超了返回 429 + 还要等几秒 |

> 前两层**不会给机器人任何反馈** —— 照常回 `success`，只是状态记成 `spam`、
> 不在页面上显示；站长在控制台里照样看得到。

#### 审核

`api.php` 顶部有个开关，默认**开着**：

```php
$COMMENT_MODERATE = true;   // 新评论先进待审核，站长点了通过才显示
```

想发出来就立刻可见，改成 `false`（或者在 `config.php` 里覆盖）即可。
控制台的抽屉里多了个**「评论」**页签：待审的会带上"待审"标记，
每条都能**通过 / 撤下 / 删除**（删主评论会连它的回复一起删）。

#### 数据与隐私

- 每条评论存：`id / parent / name / site / text / ts / status / ip`
- `ip` 存的是 **sha1(客户端 IP) 的前 8 位**，只用于限流；
  **任何公开接口都不会返回它**，原始 IP 一律不落盘。
- `comments/` 目录在 nginx 里和 `blogs/` 一个待遇：`location ^~ /comments/ { deny all; }`，
  直接访问 `comments/1.json` 是 **403**。
- 文章被**彻底删除**时，它的评论文件会一起清掉；只是"移到回收站"的话评论留着，
  撤销删除后评论还在。

#### XSS

前端**全程用 `textContent`** 渲染昵称、网址和正文，没有一处拼接用户输入成 HTML。
所以 `<img src=x onerror=...>` 这类只会原样显示出来，不会执行。
这比维护一份"过滤黑名单"可靠得多。

#### 怎么验证

`work/qa/verify-comments.js`（27 项）会真的往服务器上写评论再清理，覆盖：

发表 → 待审不可见 → 后台通过后可见 / XSS 原样显示且不执行 /
蜜罐判 spam / 秒发判 spam / 超长·非法网址·空内容被拒 /
紧随其后的第二条被限流 / 回复嵌套渲染 / `comments/1.json` 403 /
公开接口不含 ip 字段 / 没有引入任何新的第三方域名 / 后台删除 /
**最后把 `comments/1.json` 还原并断言与测试前逐字节一致**。

### ⚠️ 一个把整个背景弄丢的坑

**千万不要给 `html` 设 `background-color`。**

原理：`html` 没有背景时，`body` 的背景会**传播到画布**，于是 `.bg`（`z-index:-2`，
装着极光和纹理）和 `.rain`（`-1`）都能露出来。
一旦 `html` 有了自己的背景，`body` 就不再传播、改为自己绘制那一层，
而 `body` 是不透明的 —— 它会直接盖在 `.bg` 和 `.rain` 上面。

结果：**浅色下看不到任何纹理，深色下只剩一片纯 `#070810`（"黑夜模式一片黑，什么颜色都没有"）**。
我为了"修手机端"加过这一行，直接把整个背景装饰层弄没了。

如果将来确实需要把背景色放在 `html` 上，必须同时把 `body` 的背景改掉：

```css
html { background-color: var(--bg-0); }
body { background: transparent; }   /* 否则 body 会盖住 .bg */
```
- **切换期间会把全站 CSS 过渡临时关掉**（`html.theme-switching`）：
  View Transitions 是在主题改完后才截"新画面"的，此时若元素还在做颜色过渡，
  截到的就是旧颜色，动画结束时真画面才补上 —— 看起来就是"闪一下"。
  注意这里只关 `transition` 不碰 `animation`，否则会把圆形擦除一起干掉。
- **两个擦除动画都带 `animation-fill-mode: forwards`**：
  动画播完到伪元素树销毁之间还会渲染几帧，没有 `forwards` 的话
  `clip-path` 会失效、旧快照以整屏原样露出来（就是"闪一下"）。
  收缩那条末尾还叠了 `opacity: 0` 兜底 —— `clip-path` 依赖 CSS 变量，
  变量清掉后半径会回退到默认值。

## 🔐 关于安全的一点说明

这一版做过一轮实际的渗透测试，下面是明确的结论和仍然存在的限制。

**已经修掉的**

| 问题 | 现状 |
| --- | --- |
| 密码用裸 sha256 存，6 位数字 0.24 秒被爆破 | 改用 `password_hash()`（bcrypt，自带盐、故意慢） |
| 浏览器保存明文密码，每次请求都发一次 | 改成登录换 `sid`，浏览器只存随机会话 id，可随时注销，12 小时过期 |
| 没有任何登录限速 | 同一 IP 15 分钟内失败 8 次锁 15 分钟 |
| markdown 里的原始 HTML 会执行（持久化 XSS） | 加了白名单清洗；实测注入的 `<img onerror>` 不再执行 |
| 整份 `default.md` 可被下载，删除的文章也在里面 | `blogs/` 整个目录 deny，改由接口按需返回 |
| `default.md.bak` 可被下载，能看到删掉的内容 | 备份移到 `blogs/.backup/`（Web 不可访问） |
| 写入是"先截断再写"，中断会毁掉整个库 | 改成写临时文件 + `rename` 原子替换 |
| 没有安全响应头 | 补上 CSP / X-Frame-Options / nosniff / Referrer-Policy |

**仍然存在的限制（需要你自己权衡）**

1. **站点是纯 HTTP。** 密码虽然在传输中只有登录那一次，但仍然是明文发出去的，
   同一局域网里的人可以抓包看到。**要真正安全就得配 HTTPS**（哪怕是自签证书）。
   公网暴露的话，这个是第一优先级。
2. **整个数据库仍然是"公开内容"。** 接口只返回该看的字段，但文章正文本来就面向所有人，
   所以**不要把密码、密钥、私人信息写进正文**。
3. **`sid` 存在 `sessionStorage` 里。** 一旦站内出现 XSS，会话仍可能被偷走
   （但攻击者拿到的是可撤销的会话，不是你的密码本身）。清洗已挡住已知路径，
   真正的兜底是 CSP——目前为了内联脚本保留了 `'unsafe-inline'`，可以再收紧。
4. **没有备份策略。** `blogs/.backup/` 只保留上一版。真正重要的内容请自己定期
   把 `blogs/` 打包走。

### 密码该设多复杂

在你这台机器（40 核）上实测 bcrypt 单次约 **290 毫秒**，即单核约 3 次/秒。
按这个速度换算离线爆破（前提是 `config.php` 泄露）：

| 密码形态 | 组合数 | 同硬件预计耗时 |
| --- | --- | --- |
| 6 位纯数字 | 100 万 | **2 小时** |
| 8 位小写字母 | 2.1×10¹¹ | 48 年 |
| 8 位大小写 + 数字 | 2.2×10¹⁴ | 5 万年 |
| 12 位大小写 + 数字 | 3.2×10²¹ | 天文数字 |

结论：**8 位以上、大小写加数字就够了**；用一句好记的中文拼音短语更好。
别再用 6 位数字——`314159` 这类在上面这张表里只有 2 小时。

在线爆破现在完全不用考虑：限速把速率压到每小时约 16 次，6 位数字也要 7 年。
